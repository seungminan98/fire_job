# fire_job — 소방공사 일정 · M/M Capacity 관리 웹

소방공사 프로젝트의 **일정(간트)** 과 **월별 투입 인력(M/M, man-month) Capacity** 를
한 화면에서 관리하는 웹앱입니다.

> 설계 철학: **파일 하나 · DB 없음 · 무료.**
> 데이터는 평소 브라우저(localStorage)에 자동 저장되고, 공유는 URL/CSV 두 갈래로 안전장치를 뒀습니다.

> **공사별 훅업(Hook-up) 공정표** — `hookup.html`
> 한 공사를 골라 소방기계 · 소방전기 · 감리 · 인허가 4개 공종의 상세 공정을 간트차트로 관리합니다.
> 아래 [공사별 훅업 공정표](#-공사별-훅업hook-up-공정표--hookuphtml) 참고.

---

## 한눈에 보기

- HTML 파일 **하나로 완결** — 외부 라이브러리·CDN·서버·DB 전부 없음
- 입력하면 **자동 저장**(localStorage), 새로고침해도 유지
- **공유 URL 복사** 한 번이면 서버 없이 데이터 전달(LZ-String 압축)
- 착수일만 넣으면 **7단계 일정 자동 분배**
- **간트차트 · Capacity/Pull · 인원별** 3개 미리보기
- 표 컬럼/정렬/뷰를 자유롭게 커스터마이징

## 기술 스택

| 구분 | 내용 |
|------|------|
| 마크업/스타일 | HTML5, CSS3 (CSS 변수 기반 디자인 토큰, Flexbox/Sticky) |
| 로직 | Vanilla JavaScript (프레임워크 없음, 빌드 과정 없음) |
| 차트 | 인라인 **SVG** 직접 렌더 (꺾은선 차트), HTML/CSS 기반 간트 막대 |
| 데이터 저장 | 브라우저 **localStorage** (자동 저장) |
| 공유/직렬화 | JSON → enum 인덱스화 → **LZ-String**(MIT, 인라인) 압축 → URL 해시 |
| 입출력 | CSV 내보내기/불러오기(직접 구현한 파서·직렬화) |
| 배포 | 정적 호스팅(GitHub Pages 등) 또는 파일 직접 열기 |

**의존성 0** — `index.html` 한 파일만 있으면 동작합니다. (LZ-String도 파일 안에 인라인)

## 사용 방법

### 방법 1. 파일 직접 열기 (가장 간단, 자동저장 O)
1. `index.html` 다운로드
2. 더블클릭해서 브라우저로 열기
3. 끝. 입력 내용은 그 브라우저에 자동 저장됩니다.

### 방법 2. GitHub Pages 등 정적 호스팅
1. 이 저장소를 GitHub Pages로 배포
2. 발급된 주소로 접속해서 사용 (자동저장 동작)

> 주의: 일부 미리보기 환경(샌드박스 등)에서는 localStorage 자동저장이 막혀 있을 수 있습니다.
> 그럴 땐 화면 상단에 **빨간 경고 배너**가 뜨며, **"전체 내보내기(백업)"** 또는 **"공유 URL 복사"** 로 보관하세요.

## 사용설명서 (기능 상세)

### 1. 공사 목록 관리 (입력 표)
- 공사별 입력 항목: 공사명 · 규모(대/중/소) · 구분(경영계획/의뢰공사/자체공사) · 계약구분(입찰/단가) ·
  상태(예정/진행중/완료/hold/drop) · 연면적 · 층수 · **착수일 · 종료일** · 현단계 ·
  담당자(기계/전기/**정/부**) · 비고
- 공사 **추가 / 삭제**
- **행 순서 드래그 이동** (⠿ 핸들을 잡고 위아래로, 드롭 위치 미리보기 표시)
- **규모 색 구분**: 대 = 빨강 · 중 = 파랑 · 소 = 회색
- **구분 색 구분**: 경영계획 = 보라 · 자체공사 = 초록 · 의뢰공사 = 검정
- **상태별 행 강조**: 완료·hold·drop 행은 **회색 처리**, 완료·drop 행은 추가로 **취소선**

### 1.5 간트 편집 모드 — 드래그로 일정 조절
- 공사 목록 좌측의 **[표 입력 | 간트 편집]** 전환 버튼으로 모드 전환 (선택 상태 저장됨)
- 간트 편집 모드에서 **드래그만으로 날짜 조절**:
  - 막대 **몸통 드래그** = 공사 전체 이동(착수~종료 통째로)
  - **단계 경계선 드래그** = 해당 단계 종료일 조절(다음 단계 시작일 자동 연결, 전체 기간 유지)
  - **양 끝 드래그** = 착수일 / 종료일 변경
  - 드래그 중 날짜 툴팁 표시, 놓는 순간 자동 저장
- 상단 눈금은 **년 → 월 → 주 → 일** 계층 병합 헤더 (줌에 따라 표시 단계가 달라짐)
- **최소 단위 토글(월/주/일)** 로 배율 조절 — 일 줌에서는 주차(n주)·일 숫자·주말 표시
- 주·월 단위일 때 날짜가 **단위 경계로 스냅** — 기준을 **막날(주=일요일·월=말일) / 첫날(주=월요일·월=1일)** 중 선택

### 2. 단계 일정 자동 분배 (7단계)
- 단계: 접수 · 기획 · 설계 · 계약 · 시공 · 정산 · 인수인계
- **착수일만 넣으면 단계가 자동 분배** — 기획·설계·계약·정산·인수인계는 고정 기간,
  남은 기간을 접수 : 시공 비율로 분할
- 전체 기간이 고정 합보다 짧으면 고정분이 비례 축소
- **종료일 직접 편집 가능** — 종료일을 바꾸면 착수일~종료일 전체 기간에 맞춰 단계가 재분배됨
- **단계별 종료일 체인**: 한 단계 종료일을 바꾸면 다음 단계들이 자동으로 이어서 밀림
- **단가계약이면 '계약' → '내역검토'로 라벨 자동 전환**
- 단계 종료일은 **행별 펼치기(▸/▾)** 로 표시, 전체 펼치기/접기 버튼, 새 공사는 자동 펼침

### 3. 컬럼 커스터마이징
- 컬럼 **숨기기 / 보이기**
- 컬럼 **폭 조절** (헤더 우측 끝 드래그)
- 컬럼 **순서 이동** (헤더 드래그)
- **사용자 정의 컬럼 추가** (텍스트 / 숫자 / 선택형 드롭다운), 편집 · 삭제
- 종료일 컬럼은 기본적으로 착수일 바로 뒤에 배치됨

### 4. 정렬
- 헤더 클릭: 오름차순 → 내림차순 → 해제 순환
- **Shift+클릭으로 다중 정렬** (우선순위 1·2·3차, 헤더에 ▲¹ ▼² 표시)
- 타입별 똑똑한 비교: 규모는 대<중<소, 날짜는 날짜순, 숫자는 수치, **빈값은 항상 뒤로**

### 5. 뷰(프리셋)
- 컬럼 구성 · 순서 · 폭 · 숨김 · 정렬을 **뷰 단위로 저장**해 탭으로 전환
- 뷰 **추가 · 이름변경 · 삭제** (예: "착수일순 뷰", "규모·상태순 뷰"를 따로)

### 6. 미리보기 (3개 탭)
- **간트차트**: 각 단계를 **실제 기간만큼 이어지는 가로 막대**로 표현(색 = 단계).
  막대에 마우스를 올리면 기간·투입 M/M 툴팁 표시. **오늘 위치를 빨간 점선**으로 표시.
  좌측 표의 정렬·순서를 그대로 반영
- **Capacity / Pull**: 월별 **필요 M/M 합계 vs 가용 인원**, 가동률·판정(가능/빠듯/초과).
  상단에 **꺾은선 차트 + 가용 인원(budget) 점선**
- **인원별**:
  - **담당자 요약(피벗)**: 사람별 `정 공사 수 / 부 공사 수 / 담당 공사(중복 제외)`
  - **인원별 월 Capacity**: 사람별 월별 부담 M/M(색상 구분).
    상단에 **사람별 꺾은선 차트 + 1.0(1인 풀, budget) 점선**
  - 한 사람의 한 달 풀(full) 부담을 **1.0 M/M** 로 보고, **정 100% · 부 70%** 비중으로 합산(설정에서 조정)

### 7. M/M 설정
- 규모별 · 단계별 M/M 투입량 표
- 자동분배 기준(단계별 고정 개월수, 접수 : 시공 비율)
- 가용 인원 · 빠듯% · 초과% 임계값
- **정 비중 / 부 비중**(인원별 Capacity 합산 비율, 기본 100% / 70%)
- 기본값 복원

### 8. 저장 — localStorage 자동저장
- 입력할 때마다 브라우저(localStorage)에 자동 저장 → **새로고침해도 유지**
- 우상단에 "저장됨" 표시
- **저장 불가 환경이면 상단에 빨간 경고 배너** (새로고침 시 손실 위험 안내)

### 9. 공유 — JSON 압축 → URL (DB 없이)
- **"공유 URL 복사"** → 현재 데이터를 **배열 직렬화 + enum 인덱스화 + 단계 종료일을 일수 오프셋으로 저장 + LZ-String 압축**
  → URL 해시(`#d=...`)에 담아 클립보드로 복사
- 받은 사람이 URL을 열면 복원 제안 → 자기 localStorage에도 저장, 주소창의 긴 해시는 자동 정리
- URL이 길면 길이 경고
- **직접 수정한 단계 날짜가 그대로 보존됨**(예전 버전은 착수일로 재계산하느라 날짜가 틀어졌는데, 이를 해결)
- LZ-String은 MIT 라이선스로 HTML에 인라인 → 외부 의존 0

### 10. CSV 입출력
- **전체 내보내기(백업)**: 전체 컬럼 · 단계별 날짜 · 원본 순서 → 다시 불러오기 가능
- **현재 뷰 내보내기**: 화면 그대로(정렬 순서 · 보이는 컬럼 · 컬럼 순서) 보고/공유용
- CSV **불러오기** (기존 목록 대체 또는 추가 선택)
- **설정값**도 별도 CSV로 내보내기 / 불러오기
- 한글 깨짐 방지를 위해 UTF-8 BOM 포함

### 11. 레이아웃 · 배포
- 단일 컬럼 중앙 정렬, 표·간트는 폭에 맞게 펼쳐지고 넘치면 가로 스크롤
- **HTML 파일 하나로 완결** — 외부 라이브러리·CDN·서버·DB 전부 없음
- GitHub Pages 등 정적 호스팅에 그대로 올려 사용 가능

## 공사별 훅업(Hook-up) 공정표 — `hookup.html`

전체 공사 목록(`index.html`)이 포트폴리오 관리라면, `hookup.html`은 **한 공사 안의 상세 공정 관리**입니다.
같은 설계 철학(파일 하나 · 의존성 0 · localStorage 자동저장 · LZ-String 공유 URL)을 그대로 따릅니다.

### 공종 구성 — 사용자 정의 + 머터리얼 테마색
- 공종은 고정이 아니라 **사용자가 직접 구성**합니다 — 새 공사 만들 때 전기·기계·인허가·감리 등
  원하는 공종을 넣고, 공종마다 **머터리얼 컬러 팔레트(19색)에서 테마색**을 고릅니다.
- 같은 공종의 작업은 위에서 아래로 갈수록 **700 → 600 → 500 → 400…** 순으로 톤이 옅어져
  공종 안에서의 순서가 한눈에 구분됩니다.
- 생성 후에도 **공종·색상 관리** 버튼으로 공종 추가/이름·색·업체 변경/순서 이동/삭제 가능
  (삭제 시 그 공종의 작업은 첫 번째 공종으로 이동).
- **Jira식 계층**: 공종(Epic) > 작업(Task) > 하위 작업(Sub-Task).
  작업 행의 **+하위** 버튼으로 하위 작업(자재수급·검수·용접·가압테스트 등)을 추가하고,
  공종/작업 단위로 **접기(펼치기)** 가 됩니다(상태 저장). 상위 작업 삭제 시 하위도 함께 삭제.
- WBS 코드는 공종명 첫 글자 + 순번(기-1), 하위 작업은 점 표기(기-1.1, 기-1.2 …).
- 기본 제공 공종(표준 템플릿 매핑): 소방기계=레드, 소방전기=블루, 감리=그린, 인허가=딥퍼플.
  기존(고정 공종) 데이터는 열 때 자동 변환됩니다.

### AI 자료 밀어넣기 — `bridge.html`
PPT(.pptx)·이미지(공정표 캡처, 화이트보드 사진)·텍스트를 첨부하면 **Claude API가 읽어서
훅업 공정표 형식의 데이터로 변환 → 미리보기에서 확인·수정 → 훅업 공정표(localStorage)에 자동 입력**하는 중간다리입니다.

- 사용자 본인의 **Anthropic API 키**(`sk-ant-…`)로 브라우저에서 API를 직접 호출 — 중간 서버 없음, 키는 브라우저 밖으로 나가지 않음
- .pptx는 브라우저 안에서 압축을 풀어 슬라이드 텍스트 추출(외부 라이브러리 없이 네이티브 `DecompressionStream` 사용), 이미지는 AI가 직접 봄(vision)
- **구조화 출력(JSON Schema)** 으로 공종(기계/전기/감리/인허가/공통)·날짜·진척률·마일스톤이 정확한 형식으로만 나오도록 강제
- 결과 미리보기에서 행별 포함/제외·셀 수정 후 → **새 공사로 생성** 또는 **기존 공사에 작업 추가**(공종+작업명 중복은 자동 스킵)
- 토큰 사용량·대략적 비용 표시, AI가 불확실했던 부분은 "확인 요청"으로 함께 표시
- 사용 모델: `claude-opus-4-8`

### 전체 공사 일정과 연동
- 공사 선택 드롭다운 아래 **"전체 공사 일정에서 가져오기"** 목록에
  `index.html`(전체 일정)에 등록한 공사가 자동으로 나타납니다.
- 선택하면 공사명·착수일·준공일을 복사해 훅업 공사로 만들고,
  기간이 있으면 표준 훅업 템플릿 자동 배치 여부를 물어봅니다 (취소 = 빈 공정표).
- 이미 가져온 공사(또는 같은 이름)는 목록에서 자동으로 제외됩니다.

### 주요 기능
- **새 공사 만들기**: 공사명 · 착수일 · 준공일 (+ 기계/전기 업체, 감리사, 관할 소방서)만 넣으면
  **표준 훅업 템플릿 23개 작업이 기간에 맞춰 자동 배치** (소방시설공사업법 절차 반영: 착공신고 → … → 완공검사증명서 발급)
- **공정표 컬럼**: 코드(공종별 WBS) · 공종 · 작업명 · 담당업체 · 담당자 · 계획 착수/완료 · 기간(자동) ·
  진척률 · 상태 · 선행 · 마일스톤 — 공종 → 착수일 순 자동 정렬
- **간트차트**: 공종별 색 막대, 막대 안 어두운 부분 = 진척률, ◆ = 마일스톤, 빨간 점선 = 오늘,
  **계획완료 경과 & 미완료 = 지연 자동 표시**(빨간 테두리·집계).
  상단 눈금은 전체 일정의 간트 편집과 동일한 **년→월→주→일 계층 병합 헤더** —
  최소 단위 토글(월/주/일)로 배율 전환, 일 줌은 주차(n주)·일 숫자·주말 강조 (선택 상태 저장)
- **막대(또는 작업명) 클릭 → 상세 창**: 실제 착수/완료 · 메모(검측 결과, 지적사항) · **현장 사진**
- **사진 첨부 — URL 없이도 가능**: 파일 업로드 시 브라우저에서 자동 압축(긴 변 1280px, JPEG)해
  base64로 localStorage에 저장. 이미지 URL 붙여넣기도 지원. 저장 사용량 게이지(≈5MB 한도) 표시
- **요약 스탯**: 기간 가중 전체 공정률 · 완료/진행중/지연 건수 · 준공 D-day
- **보관/공유**: JSON 백업(사진 포함) · 공유 URL(LZ-String, 업로드 사진은 용량 문제로 제외) · 공정표 CSV

## 업무 표준 매뉴얼 — `process.html`

"이걸 하고 나면 이걸 하고, 조건이 이러면 저리로 간다"는 **업무 프로세스를 단계별로 입력하면
플로우차트가 자동으로 그려지는** 매뉴얼 작성 페이지입니다.

- 단계 유형: **시작 · 작업 · 판단(조건 분기) · 종료** — 표에서 제목/내용/담당/다음 단계를 입력
- **판단 단계는 분기별 라벨과 이동할 단계**를 지정 — 앞 단계로 되돌아가는 분기(보완 후 재접수 같은
  재작업 루프)는 왼쪽 점선 화살표로 그려집니다
- 플로우차트: 사각형=작업, 마름모=판단. 노드를 클릭하면 팝업 대신 **그 노드 바로 아래로 상세 패널이
  펼쳐져** 화면 전환 없이 바로 읽고 편집할 수 있습니다(같은 노드 재클릭·✕·Esc로 접힘)
- **상세 패널에서 참고 링크·이미지 첨부**: 링크(라벨+URL), 이미지 업로드(자동 압축, 긴 변 1280px)
  또는 이미지 URL — 본문·플로우차트에 첨부 개수 배지가 표시되고 클릭하면 크게 볼 수 있습니다
- **동시 진행 단계**: 편집 표의 "동시"를 켜면 바로 위 단계와 한 묶음이 되어 **같은 번호(5-1, 5-2)**
  로 매겨지고 플로우차트에 나란히 그려집니다 — 예: 감리자 지정 신고와 착공신고를 같이 제출
- **선행 조건**: 상세 패널에서 "선행 단계"를 지정하면 매뉴얼 본문에 "선행: …"으로 표기되고
  플로우차트에 **파란 점선 화살표**로 그려집니다 — 예: 실시설계(AFD)가 나와야 입찰 가능,
  시공사가 선정되어야 착공신고 가능 같은 유기적 의존 관계
- **각 단계는 폴더**: 단계 안에 **세부단계(하위 프로세스)** 를 몇 단계든 중첩해 담을 수 있습니다.
  플로우차트 노드 왼쪽 위의 폴더 표시, 편집 표의 "세부" 버튼, 상세 패널의 "세부단계 열기"로
  폴더를 열듯 안으로 들어가고, 상단 경로 표시줄(브레드크럼)로 되돌아옵니다.
  매뉴얼 본문에는 전체 계층이 1 → 1.1 → 1.1.1 번호로 들여쓰기되어 인쇄에도 그대로 나옵니다
- **매뉴얼 본문**(단계 상세)이 함께 렌더링되고, **인쇄** 버튼으로 플로우차트+본문만 출력(PDF 저장)
- 매뉴얼 여러 개 관리, JSON 백업/불러오기
- **내장 템플릿 2종** ("+ 새 매뉴얼"에서 선택, 빈 매뉴얼도 가능):
  - **건축허가 연계 소방공사(동의 대상)** — 건축허가·소방 동의(허가용 러프 도면) → 실시설계(AFD)
    → 입찰·시공사 선정 → 감리자 지정 + 착공신고(동시 진행 5-1/5-2) → 시공(샵드로잉 승인 →
    AFC 배포 → 설계변경 시 재작성 루프) → 완공검사 → 증명서 발급·건축사 제출 →
    건축물 사용승인까지 12단계 + 세부단계, 선행 조건 연결 포함.
    건축허가 폴더에 **성능위주설계(PBD) 분기** — 대상(시행령 9조: 연면적 20만제곱미터 이상,
    50층·200m 이상 아파트, 30층·120m 이상, 대형 창고, 지하연계 복합건축물, 터널 등)이면
    사전검토(건축심의 전, 기본설계 수준) → 신고·본심의(건축허가 신청 전, 화재·피난 시뮬레이션
    포함) 2단계 심의로, 비대상이면 일반 동의로 진행 — PBD 정의·대상 기준·법제처 조문 링크 포함
  - **소방시설 단독공사** — 설계 → 착공신고 대상 여부 판단 분기 → 감리 지정·착공신고 →
    시공(샵드로잉·AFC 관리) → 완공검사 → 증명서 발급·준공 7단계 + 세부단계 16개
  - **소방공사 발주·도급 기준(분리발주·하도급)** — 소방시설공사업법 제21조(분리도급 원칙)·
    제22조(설계·감리 하도급 금지, 시공 일부 1회 하도급·재하도급 금지)와 시행령 제11조의2
    (분리도급 예외: 긴급공사, 기밀공사, 1천제곱미터 이하 비상경보설비, 대안·일괄·기술제안입찰,
    국가첨단전략산업 시설 = 반도체 공장 등(5호의2, 2024.4. 신설), 소방청장 인정 재개발·재건축)
    판단 플로우 — 각 단계에 법제처 국가법령정보센터 조문 링크 첨부
- 저장: localStorage `fireProcess.v1`

## 법규 계산기 — `calc.html`

숫자만 넣으면 법규 충족 여부를 **그림으로 판정**하는 시각화 계산기입니다. 입력값은 localStorage(`fireCalc.v1`)에 자동 저장됩니다.

- **건폐율·용적률** (건축법 제55조·제56조): 대지면적·건축면적·지상 연면적·법정 한도를 슬라이더/숫자로
  입력하면 건폐율·용적률 %, 한도 대비 판정, 여유(추가 가능) 면적을 계산하고 —
  평면(대지 위 건축면적 사각형)과 입면(연면적을 층으로 쌓은 개념도)으로 동시에 그려줍니다
- **살수장애 1 — 보 인근 헤드** (NFTC 103): 헤드 반사판~보 수평거리와 반사판·보 하단 단차를 넣으면
  수평거리 구간별 허용 기준(0.75m 미만 = 보 하단보다 낮게 / ~1m = 0.1m / ~1.5m = 0.15m / 이상 = 0.3m)
  으로 적합/부적합 판정 — 천장·보·헤드·살수 패턴 단면도에 치수가 실시간 표시되고 기준표의 해당 행이 강조됩니다
- **살수장애 2 — 살수공간**: 헤드 반경 60cm 살수공간(벽은 10cm) 확보 여부를 평면도(원+장애물)로 판정
- 판정은 참고용 — 실제 적용 전 법제처 원문·관할 소방서 확인 문구와 조문 링크 포함

## 접속 암호 게이트
- 네 페이지(`index.html` / `hookup.html` / `bridge.html` / `process.html`) 진입 시 **접속 암호**를 묻습니다.
- 인증은 탭 단위로 유지되고(같은 탭에서 페이지 이동 시 재입력 불필요),
  **"이 브라우저에서 로그인 유지"** 를 체크하면 브라우저에 저장됩니다.
- 소스에는 암호의 **SHA-256 해시만** 들어 있습니다 (평문 없음).
- **암호 변경 방법**: 새 암호의 해시를 구해 각 파일 상단 게이트 스크립트의 `HASH`/`FB` 값 교체
  ```bash
  node -e 'const c=require("crypto");const pw="새암호";
    console.log("HASH:",c.createHash("sha256").update(pw,"utf8").digest("hex"));
    let h=5381;const b=Buffer.from(pw,"utf8");for(const x of b)h=((h*33)^x)>>>0;
    console.log("FB:",h.toString(16)+"-"+b.length);'
  ```
- **한계**: 프론트엔드 전용 간이 잠금입니다. 개발자 도구를 아는 사람은 우회할 수 있으므로
  (localStorage 데이터도 열람 가능) "지나가는 사람 차단" 용도로만 쓰고,
  진짜 기밀 데이터라면 백엔드 인증이 필요합니다.

## 주의사항
- localStorage는 **브라우저·기기마다 별도**입니다. 다른 PC에서 이어 작업하려면 CSV/URL로 옮기세요.
- 브라우저 데이터(캐시/사이트 데이터)를 지우면 저장 내용도 사라집니다 → 중요 데이터는 CSV 백업 권장.
- 공유 URL은 길어질 수 있어 일부 메신저에서 잘릴 수 있습니다. 길이가 길면 CSV도 함께 보관하세요.
